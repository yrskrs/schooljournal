# 1.4.6: зберігання образів і структура проєкту

## Образи

Один механізм scripts/image_retention.py для вебоновлювача й консольного update. Очищення запускається тільки після перевіреного успішного оновлення; п’ять версій включають активний образ і останній відкат. Захищені всі контейнери, включно зі зупиненими. Якщо захищених більше п’яти, вони залишаються з попередженням. Чужі образи/теги, updater, code_runner, Nextcloud, PostgreSQL, BuildKit-кеш, томи, дані та резервні копії не видаляються.

Кілька тегів одного ID не збільшують кількість версій. Перед кожним видаленням повторно перевіряються контейнери та відповідність тега запланованому ID. Немає force або глобального prune. Помилка очищення не відкочує працездатне оновлення.

## Перевірки

Окремі сценарії охоплюють межі проєктів, сторонні теги, активні/зупинені контейнери, відкат, зміни тегів/контейнерів після планування, відмову Docker та порядок очищення після health-check. Перевірено Linux-обгортки з іншої папки й шляхом із пробілами без запуску Qt. Повний GUI та Windows на цій Linux-машині не запускалися. Результати фактичних перевірок наведені нижче.
