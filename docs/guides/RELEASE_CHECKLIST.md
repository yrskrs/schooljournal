# Наступний реліз

1. Завершити зміни й оновити інструкції, README та API-контракт.
2. Підняти SemVer у VERSION. Додати запис на початок RELEASES.json; оновити CHANGELOG.md.
3. Запустити Django check, перевірку міграцій, серверні тести, JavaScript і Bash.
4. Перевірити production Compose на окремому проєкті з вигаданими даними: початкове створення суперадміністратора в браузері, закриття форми, міграція наявного адміністратора, вхід, реєстрація, API, backup/restore, update і відкат невдалого update.
5. Перевірити мобільний і настільний інтерфейс. Реальний nz.ua тестувати на дозволеному тестовому журналі.
6. Переконатися, що .env, медіа, копії, робочі бази, nz.uz та samples не входять у коміт.
7. Створити гілку, коміт і PR. Дочекатися GitHub Actions. Після погодження опублікувати й за потреби позначити тегом vX.Y.Z.
8. На сервері виконати update.sh до опублікованої ревізії, перевірити healthz і версію. Зберегти pre-update backup на іншому носії.

Для розгортання сервера використовуйте опубліковану гілку main через HTTPS. Локальний Git bundle дозволяє перевірити історію або перенести код без мережі; update.sh потребує Git checkout.
