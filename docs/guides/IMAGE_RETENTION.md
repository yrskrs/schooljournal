# П’ять останніх образів сайту

Після успішної перевірки нового випуску вебоновлювач і консольний update запускають спільне очищення. Зберігаються п’ять різних образів цього застосунку: робочий образ, останній образ для відкату та найновіші інші збірки за часом створення Docker-образу. Кілька тегів одного ID рахуються як одна версія.

Перед видаленням перевіряються всі контейнери, включно із зупиненими. Якщо понад п’ять образів ще використовуються контейнерами або захищені для відкату, вони зберігаються, а журнал пояснює перевищення. Видалення не примусове: чужі теги, інші проєкти, PostgreSQL, code_runner, updater, Nextcloud, томи та резервні копії не очищаються.

Спочатку переглянути план із кореня проєкту:

```bash
python3 scripts/image_retention.py --project schooljournal
```

Застосувати той самий план із повторною перевіркою контейнерів і тегів:

```bash
python3 scripts/image_retention.py --project schooljournal --apply
```

Власні образи визначаються лише за назвами репозиторіїв цього застосунку; старі образи без тегів — за OCI source/version. Невідомі, базові та спільні образи не видаляються. У CLI також враховується останній відкат із backups/update_status.json. За зміни тега чи появи нового контейнера очищення пропускає відповідний образ.

Якщо Docker недоступний або не дає видалити образ, успішне оновлення не відкочується: з’являється попередження. Примусового видалення, глобального system/image/builder prune немає. BuildKit-кеш не є історією версій і цим механізмом не очищається; його розмір перевіряйте окремо через docker system df.
