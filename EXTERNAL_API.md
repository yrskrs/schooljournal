# API журналу та сервера робіт

Налаштування доступні в кожному журналі через кнопку **«Профілі та API»**. Увійти через nz.ua можна без профілю, створеного адміністрацією. Під час першого входу створюється особистий профіль з окремим простором даних. Пароль nz.ua не зберігається. Кнопка **«Завантажити»** у списку nz.ua створює локальний журнал з онлайн-записів; після локальної роботи вивантаження до nz.ua запускається явно, з переглядом змін.

Локальний профіль — додатковий доступ до конкретного журналу, підтверджений його логіном і паролем. **«Відв’язати локальний профіль»** видаляє цей доступ; власником залишається особистий профіль nz.ua. Уроки, учні, оцінки та онлайн-прив’язки зберігаються. Уже наявний акаунт nz.ua, підключений до адміністративного профілю, отримує окремий особистий профіль при наступному вході через nz.ua; додатковий доступ старого профілю зберігається до відв’язування.

## Список учнів

`GET /api/v1/journals/{journal_id}/students/`

Заголовки:

```http
Authorization: Bearer КЛЮЧ_ЦЬОГО_ЖУРНАЛУ
Accept: application/json
```

API спочатку вимкнено. Виберіть поля відповіді, увімкніть доступ і створіть ключ. Новий ключ показується один раз; у базі зберігається його SHA-256 відбиток. Заміна ключа одразу відкликає попередній. За потреби задайте термін дії. Ключ у URL / параметрах не приймається. Навіть звичайна авторизована сесія не замінює ключ API.

Приклад з дозволеними полями `id`, `nz_student_id`, `name`:

```json
{
  "schema_version": 1,
  "journal_id": 42,
  "students": [
    {"id": 101, "nz_student_id": "nz-example-101", "name": "Вигаданий Учень"}
  ]
}
```

Доступні поля: `id` (локальний ID), `nz_student_id`, `internal_id`, `name` (ПІБ), `class` (назва класу), `status`. Відповідь містить лише вибрані поля та учнів з активним зарахуванням до класу журналу. Оцінки, відвідування, дата народження, телефони та інші профільні дані через цей API не надаються. Невідомий / вимкнений / прострочений ключ: HTTP 401. Дозволено лише GET; відповідь має `Cache-Control: no-store`.

## Отримання оцінок із сервера робіт

Можна додати кілька підключень для одного журналу. Потрібна повна адреса JSON маршруту; адреса сайту `http://192.168.1.13:8080/` стане придатною після появи такого маршруту. Приклад майбутньої адреси: `http://192.168.1.13:8080/api/grades`.

Після натискання **«Отримати оцінки»** журнал виконує GET на задану адресу:

```http
GET /api/grades?journal_id=42&nz_journal_id=online-example&date_from=2026-09-01&date_to=2026-10-10
Authorization: Bearer КЛЮЧ_СЕРВЕРА_РОБІТ
Accept: application/json
```

Ключ сервера робіт окремий від ключа списку учнів. Порожнє поле при редагуванні зберігає наявний ключ; позначка «Прибрати збережений ключ API» його видаляє. Значення ключа не показується повторно в HTML. Адреса має бути HTTP/HTTPS; адреси внутрішніх служб, loopback / link-local, перенаправлення та URL з логіном/паролем не приймаються. З’єднання: 5 с на підключення, 20 с на читання; відповідь до 2 МБ / 1000 оцінок. Коли відповідь більша, використовуйте коротший період.

Рекомендований формат відповіді:

```json
{
  "grades": [
    {
      "id": "work-2026-10-09-101",
      "student_id": 101,
      "date": "2026-10-09",
      "lesson_number": 1,
      "value": 10,
      "is_ai": true,
      "approved_by_teacher": false
    }
  ]
}
```

- `id`: стабільний унікальний ID оцінки / роботи в межах підключення. Різні роботи мають різні ID; повторний запит тієї самої відповіді не створює дублів і не скасовує рішення вчителя.
- `student_id`: локальний ID, ID nz.ua або внутрішній ID відповідно до налаштування підключення. Зіставлення за ПІБ не виконується. Неунікальний або відсутній ID дає повідомлення про помилку.
- `date`: дата **уроку, до якого належить оцінка**, у форматі `YYYY-MM-DD`. Це не дата пізнішої перевірки роботи. Потрібен наявний навчальний урок у журналі й дата в обраному періоді навчального року.
- `lesson_number`: номер уроку на дату. Необов’язковий, якщо на дату є рівно один навчальний урок; підсумкові колонки не використовуються.
- `value`: ціле число / рядок від 1 до 12.
- `is_ai`, `approved_by_teacher`: JSON boolean `true` / `false`, не рядки. Якщо `is_ai` не надано, оцінка обережно вважається оцінкою ШІ; відсутність схвалення означає `false`. Сервер робіт має виставляти `approved_by_teacher: true` лише після явного схвалення вчителем. Оцінка ШІ зі схваленням на сервері робіт може бути остаточною.

Назви полів налаштовуються у формі підключення. Дозволено вкладені шляхи через крапку, наприклад `data.grades` або `student.nz_id`. Для кореневого масиву JSON залиште поле списку порожнім.

## Попередні оцінки, конфлікти та схвалення

Оцінка з робіт має позначку **API**, назву джерела та ID роботи. Для оцінки ШІ без схвалення показано **«ШІ · ?»** у клітинці та **«ШІ · попередня»** в описі: вона має окрему клітинку з позначкою, не входить до середнього / тематичних / семестрових підсумків, не включається в локальні XLSX/PDF як остаточна та не може бути вивантажена в nz.ua навіть при прямому виклику сервісу синхронізації.

Коли клітинка заповнена іншою оцінкою, містить ручне очищення або відвідування, імпорт не замінює її. Запис потрапляє на сторінку **«Оцінки з робіт»** як конфлікт із показом поточного й запропонованого записів. Заміна потребує окремої позначки «Замінити запис у клітинці» та схвалення. Відхилення зберігає рішення в історії.

Схвалення робить оцінку остаточною локально; подальше вивантаження до nz.ua все одно запускається вчителем через перегляд змін. Зміна даних API після схвалення не замінює остаточну оцінку автоматично; вона створює конфлікт для нового рішення. Якщо API змінює учня / урок для вже наявного ID роботи, запис відхиляється: для іншого призначення потрібен новий ID.

Оцінки не створюють нових онлайн-колонок автоматично. Для вивантаження потрібні наявні `nz_schedule_id` уроку та `nz_student_id` учня. Помилки й лічильники кожного отримання доступні під списком імпортованих оцінок. Фонових запитів / вивантажень немає.
