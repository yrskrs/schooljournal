## 1.4.0 — 2026-10-24 — Централізовані підключення та окремі дії синхронізації

- Одна сторінка підключень: мережеві профілі з одним host, майстер, UUID, версія, права ключа й зрозумілі помилки 401 / 403.
- Перед токеном перевіряються source та instance_id; автовизначення пам’ятає робочу мережу, ручний режим не перемикається непомітно. Старі ID, класи, історія й оцінки зберігаються.
- Наявні адреси та Server Groups мігрують у центральну модель; токени журналу зашифровано. Приватний SECRET_KEY потрібний для відновлення.

- У журналі один блок синхронізації з окремими «Передати учнів» / «Забрати оцінки», періодом, часом, підсумками та посиланнями на конфлікти. Отримання оцінок не надсилає список приховано.
- Урок за замовчуванням діє лише для нових робіт; окремий вибір роботи має пріоритет. Ручні й погоджені оцінки та попереднє розміщення збережено.

## 1.3.36 — 2026-10-21 — Вибір уроку для оцінок тестів і завдань

- Дія «Обрати урок» у журналі й розділі API показує роботи за період завершення. Учитель обирає дату, номер і тему з наявних звичайних уроків свого журналу та отримує оцінки лише потрібної роботи.
- Вибір зберігається для конкретної сесії тесту або завдання та застосовується до наступних пізніх результатів, зокрема через підтверджені резервні адреси. Період отримання робіт не обмежує вибір уроку в межах того самого навчального року. Передбачено повернення до автоматичного вибору.
- Попередній перегляд не імпортує оцінки, не передає списки й не змінює відповідності учнів. Підтвердження використовує перевірений перегляд поточного вчителя; прострочені дані й змінені підключення відхиляються.
- Уже імпортовані оцінки не переносяться й не дублюються при зміні уроку. Ручні оцінки та відвідування захищені конфліктами; окремі учні отримують оцінки у власний журнал.
- Виправлено пріоритет відомої сесії над датою пізнього завершення, змішування незалежних сесій за work_id, кеш уроків окремих журналів та зайві відповідності за збігом ПІБ.
- Виправлено права публічного коду при CLI-оновленні та відновленні під приватною маскою файлів; секрети зберігають приватні права.
- Додано інструкцію /help/#grade-lesson, регресійні та браузерні перевірки. Адитивна міграція 0019 створює таблицю вибору уроків; наявні оцінки не змінюються.

## 1.3.35 — 2026-10-21 — Надійна синхронізація оцінок за допройдені тести та автоматичне зіставлення учнів

- Оцінки за тести («schooltest») і завдання («schoolwork»), допройдені учнями пізніше (іншого дня, у вихідні або ввечері), автоматично прив’язуються до відповідного уроку сесії або завдання, навіть якщо на дату завершення тесту за розкладом уроку не було.
- Перед імпортом пакету оцінок виконується попередній аналіз сесій тестування та завдань: урок, визначений для першого учня сесії, застосовується до решти робіт цієї ж сесії незалежно від порядку їх надходження.
- Якщо сесія тестування проходила поза днями розкладу, урок визначається за попередньо збереженою історією сесії, ідентифікатором роботи (work_id) або за збігом теми уроку з назвою тесту.
- Учні, які проходили тест самостійно (без попереднього зіставлення списків чи з відмінностями в написанні ПІБ), автоматично зіставляються з учнями відповідного класу за українським написанням ПІБ із автоматичним створенням прив'язки і виставленням оцінки в журнал.
- Період запиту оцінок на вкладці місяця розширено буфером (7 днів до початку та 14 днів після закінчення місяця), щоб роботи, завершені на межі місяців, не втрачалися під час синхронізації.
- Виправлено на всіх журналах і класах; додано модульні регресійні тести. Нових міграцій немає.

## 1.3.34 — 2026-10-19 — Прості API та сповіщення

- «API та обмін» об’єднує підключення журналів, сповіщення й списки учнів. Основний вигляд показує потрібні дії; технічні параметри збережені у «Додаткових налаштуваннях».
- Постійні сповіщення містять журнал, причину та перехід до конкретного підключення або перевірки результатів. Помилки списків, оцінок і перевірки зв’язку відстежуються окремо; повторний успіх відповідної операції прибирає сповіщення, зберігаючи історію.
- Кнопка «Резервна адреса» додає другу адресу підтвердженого сайту, зберігає основну та копіює клас, предмет і відповідності учнів. Інші екземпляри сервісу не можуть підмінити джерело.
- Автоматичне перемикання працює також після відмови запиту API. Оцінки імпортуються один раз після успішного отримання; вимкнені адреси пропускаються.
- Перевірки зв’язку зберігаються в історії й не перезаписують підтверджений instance_id іншим сервісом. Помилка чи зауваження після синхронізації залишає у журналі посилання на сповіщення.
- Додано зрозумілу інструкцію /help/#api-start та регресійні перевірки. Нових міграцій немає.
- Локальний режим Docker автоматично перезавантажує Python після змін коду та метаданих, щоб нові шаблони не працювали зі старими маршрутами. README пояснює перезапуск після ручного монтування коду й оновлення статичних файлів.

## 1.3.31 — 2026-10-18 — Виправлення передачі учнів та знеособлені звіти діагностики

- Передача списків використовує ID з підтвердженого звіту того самого сервісу й класу. Текстові й додаткові числові псевдоніми результатів більше не підміняють ID списку та не спричиняють HTTP 400.
- Підтвердження й об’єднання додаткових профілів зберігають решту відповідностей учня. Неоднозначний список блокується до мережевого запиту з поясненням у діагностиці.
- Кнопка «📤 Учні» обробляє JSON на поточній сторінці без переходу GET на маршрут POST та помилки HTTP 405. При відмові показується пояснення сервера.

- Адміністративна команда audit_integrations перевіряє всі локальні класи, учнів і підключення лише читанням БД, без мережевих запитів.
- Версія JavaScript у URL залежить від вмісту файла; повідомлення показуються як текст. Оновлено довідку й додано регресійні перевірки до CI. Нових міграцій немає.

## 1.3.27 — 2026-10-18 — Спливаючі сповіщення (Toast), групування серверів за локаціями (дім/школа) та автоматичний вибір активної IP-адреси

- Впроваджено сучасну систему спливаючих карток-сповіщень (Floating Toasts), зафіксованих у верхньому правому кутку екрана поверх усього контенту, які залишаються видимими при будь-якій прокрутці сторінки, мають таймерний індикатор, підтримку призупинення при наведенні миші та кнопку швидкого закриття.
- Додано підтримку групування підключень сервера (`server_group`): кілька IP-адрес одного й того самого фізичного сервера (наприклад, ноутбук вдома 192.168.1.x та в кабінеті інформатики школи 192.168.0.x) тепер можна об'єднати в єдину логічну групу.
- Додано мітки розташування (`location_tag`): можливість позначати підключення як «Дім», «Школа / Кабінет інформатики» чи власною міткою з кольоровими індикаторами в інтерфейсі.
- Реалізовано надшвидке зондування доступності портів (`probe_connection_reachability`) та автоматичний failover: при отриманні оцінок журнал опитує активну доступну в поточній мережі адресу сервера.
- Усунено помилкові повідомлення (false alarms): якщо одна з IP-адрес згрупованого сервера вимкнена або недоступна в поточній локації, система більше не блокує синхронізацію та не виводить лякаючі помилки про недоступність, а безперешкодно отримує дані з активної адреси.
- Додано випадний селектор вибору точки підключення («⚡ Автовибір (Дім/Школа)» чи конкретний IP) прямо у статусному рядку журналу для миттєвої перевірки та роботи.
- У «Центрі керування API та синхронізації» додано форму швидкого групування серверів в один клік та перемикання основного підключення за замовчуванням.
