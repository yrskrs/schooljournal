# Перевірка релізу 1.3.32 — 18.10.2026

Реліз уточнює результат кнопки «📥 Оцінки» та вибір адрес сервісів тестів і завдань. Звіти конкретного встановлення, контрольні суми й резервні копії зберігаються приватно; до Git не входять ПІБ, оцінки, ключі та сирі відповіді джерел.

## Поведінка

- Перед отриманням оцінок журнал повторює передачу списку учнів. Це враховує зміни складу класу й ігнорування після тимчасової недоступності джерела. Попередження про відповідності учнів належить цій підготовчій операції.
- AJAX-відповідь кнопки оцінок тепер має `operation: "grades"`, кількості імпорту та повідомлення, яке починається з результату оцінок. Зауваження щодо списку йдуть далі. Flash-копії повідомлень споживаються, щоб не повторитися при оновленні сторінки. Звичайні POST зберігають перенаправлення.
- «📤 Учні» має `operation: "roster"`. Кнопки мають явних власників форм, а JavaScript перевіряє тип відповіді та читає маршрут із атрибута форми, який не підміняється полем `action`.
- Адреси v2 з однаковим підтвердженим `instance_id` групуються в межах одного журналу, типу джерела, класу й предмета. Для групи виконується один імпорт. При недоступності вибраної адреси доступна резервна адреса того самого екземпляра; інші екземпляри та контексти не підміняють джерело.
- Перед передачею списку й читанням оцінок перевіряється живий `instance_id`. Пошук завершується після першої доступної та підтвердженої адреси. Вимкнені адреси прибрано з вибору активних підключень.

Нові регресії перевіряють пріоритет повідомлення оцінок, відсутність повторного flash, імпорт без дублювання адрес, межі групування, резервну адресу при явному виборі, відмову іншого живого екземпляра та повторне підтвердження після зміни адреси чи ключа. Браузерний сценарій і порядок запуску збережено у `tests/ux/README.md`.

Успішний HTTP-запит не вирішує неоднозначності відповідностей, конфліктів ручних оцінок чи недопустимих значень шкали. Такі записи збережені для рішення вчителя. Перевірка не виконувала масового запису історичних оцінок; платний ШІ та передача оцінок до nz.ua не запускалися.

## Оновлення

Версію узгоджено у VERSION, RELEASES.json, CHANGELOG.md, README, Dockerfile та стандартному образі Compose; оновлено довідку `/help/` і документацію інтеграції. Приватні звіти виключено також із Docker build context.

Оновлюйте чистий checkout main через штатний розділ «Оновлення системи» або `./update.sh`. Штатний процес створює резервну копію та перевіряє версію запущеного образу. Нових міграцій і відновлення БД для переходу на 1.3.32 не потрібно.

## Додатковий реліз 1.3.33

Під час реального CLI-оновлення виявлено, що спільний umask 077 залишає змінені Git файли метаданих із правами 0600. Контейнер із непривілейованим користувачем не може прочитати змонтовану версію, тому /healthz/ повертає 500. Окремо виявлено неможливість заміни теки коду іншого власника під час відкату. Попередній сервіс відновлено; контрольні суми всіх перевірених моделей збіглися з початковими.

Реліз 1.3.33 задає 0644 лише для трьох публічних файлів метаданих у CLI та вебоновлювачі, зокрема після відкату. Секретні файли не змінюються. Перед зупинкою запису та заміною БД перевіряються доступність усіх тек коду й відсутність небезпечних посилань. Архівне встановлення виконує таку перевірку також до першого видалення файла. Інструкція першого переходу зі старого CLI збережена в DEPLOYMENT.md.

Дві нові регресії перевіряють CLI/вебправа публічних файлів, збереження приватного .env та відмову символічного посилання на нього. Ще дві перевіряють відсутність часткового видалення коду при недоступній теці чи посиланні. Реліз включає всі виправлення синхронізації 1.3.32 і не потребує нових міграцій.

Повторний повний набір: 547 Django-тестів та 19 службових тестів (1 пропущено), успіх. Django check, відсутність нових міграцій і синтаксис Bash перевірено.
