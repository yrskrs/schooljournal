# Три образи, реальний HTTP і окремий PostgreSQL

Потрібні локально зібрані version-tagged образи з INTEGRATION.md та Docker Compose. Це окремий проєкт `school-api-checks`, без робочих `.env`, томів чи БД. Дані вигадані, PostgreSQL у tmpfs. Порти 19000/19080/19085 слухають лише 127.0.0.1; перевірте, що вони вільні.

```bash
docker compose -f tests/integration/compose.yaml up -d --wait
python3 tests/integration/run.py
```

Скрипт ініціалізує фікстури один раз та перевіряє списки, конфлікти, offline/retry, кнопки, CSRF/права, шкали, ретейки, пагінацію та restart вебконтейнерів. Повторний запуск потребує свіжих тестових DB-контейнерів. Після перевірки `docker compose -f tests/integration/compose.yaml down` прибере лише цей тестовий проєкт, без `-v` і без глобального очищення. Перезапуск DB-контейнера стирає лише його тестовий tmpfs.

Актуальні типові образи: schooltest5 1.6.7, schoolwork2 4.5.6, schooljournal 1.3.30. Їх можна явно замінити через `CHECK_TEST_IMAGE`, `CHECK_WORK_IMAGE`, `CHECK_JOURNAL_IMAGE` для перевірки підтримуваних версій, без зміни робочої конфігурації. Сценарій також перевіряє справжнє збереження відповідності з локалізованої форми, ігнорування та відновлення через HTTP, виправлення ігнорованої оцінки у джерелі й сімейну форму.

Після повного `run.py` виконайте `python3 tests/integration/deletion_checks.py`: перевіряє справжні POST/CSRF-форми підтвердження, видалення профілю/здач/файлів, збереження оцінок класу, мінімальні позначки проти повторної появи, окремий позакласний журнал і перезапуск. Використовує лише синтетичний Compose-проєкт. Якщо задаєте CHECK_*_IMAGE, передавайте ті самі змінні обом командам.
