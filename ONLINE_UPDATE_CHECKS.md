# Перевірка онлайн-оновлень 1.3.15

Дата: 2026-10-12. Гілка: main окремого репозиторію schooljournal.

## Виправлено

- Живий stdout/stderr Docker-збірки, backup, міграцій і restore; обмеження часу та завершення всієї групи процесів.
- Атомарне резервування операції до відповіді API, job_id, блокування повторного запуску й CLI-обслуговування.
- 100% лише після перевірки реально запущеного image ID та версії /healthz з доступом до БД.
- Відкат коду, попереднього образу, БД та файлів із перевіркою готовності; running зберігається до завершення відновлення.
- Атомарний persistent status; перерваний запуск стає явною помилкою після рестарту updater.
- Переклад bind-шляхів між контейнером updater і Docker-хостом через приватну тимчасову Compose-конфігурацію.
- Усі сайти мають встановлений changelog, перевірку GitHub, HEAD-перезбірку, фінальний результат і копіювання діагностики.
- Для початкових образів із VCS_REF=local використовується найближча ревізія з номером попередньої версії; image ID зберігає точний код контейнера. Нові збірки містять реальний Git SHA.

## Перевірки

- Тести механізму: живий вивід, тайм-аут, збереження помилки, duplicate start, persistent success/interruption, GitHub offline, формати CHANGELOG.
- JavaScript: синтаксис, межа 99% для running, текст помилки/відкату, успіх, ігнорування статусу іншого job_id.
- Регресійні тести застосунку: 475, пройдені з синтетичними даними; робочі БД не використовувалися для unit-тестів.
- Docker-збірки, реальні HEAD-перезбірки, автоматичний відкат після контрольованого збою та незалежний запуск пройдені.

## Межі

Контейнер updater має керування Docker-хостом і не публікує порт назовні. Під час міграцій/відкату вебсервіс короткочасно недоступний. За невдалого відкату інтерфейс зберігає його точну помилку та шлях копії; без підтвердження готовності успіх не показується. GitHub наразі перевіряється у main, а коміти з тим самим номером версії встановлюються після отримання коду та HEAD-перезбірки.

## Результати реальних перевірок

- HEAD-перезбірка завершила всі п’ять етапів із 100% та state=success. Перевірено точний image ID вебсервісу (і воркера, якщо є) та версію HTTP /healthz з доступом до БД.
- Після запуску справжнього кандидата контрольовано згенеровано помилку. Автоматичне відновлення завершилося state=error, rolled_back=true, rollback_error=null; перевірено повернення образу, коду, БД і файлів. Початкова причина збережена для копіювання.
- Сайт перевірено з повністю зупиненими застосунками, updater та PostgreSQL двох інших проєктів. Власний healthcheck, вхід, авторизований кабінет і сторінка оновлення повернули HTTP 200. Усі контейнери повернуті після перевірки.
- Кількість записів: ШколярТест — 92, SchoolWork — 1155, SchoolJournal — 743 (сесії не враховано). Медіа: 6 / 3017 / 0 файлів відповідно. Контрольні суми файлів збережені. Хеші предметних таблиць збережені; змінюється службовий roster_state фонової синхронізації та last_login адміністратора під час тестового входу.
- Сторінки й API перевірено на чинних Docker-образах; JavaScript додатково перевірено на обробку progress, rollback, error та stale job_id. Браузерна візуальна перевірка недоступна в цьому середовищі.

Виявлені під час Docker-перевірок проблеми виправлено: Host внутрішнього healthcheck, відсутні/пошкоджені старі образи (container snapshot та export/import), scripts у Docker-контексті SchoolWork, Alpine realpath, generic aliases після recreate. Перевірка 121,4 МБ архіву (1,7 ГБ медіа) тепер займає 6,6 секунди замість кількох хвилин; обмежене читання не накопичує весь великий файл у потоковому буфері.
