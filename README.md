# Електронний шкільний журнал — 1.3.36

Поточний випуск: **1.3.36** — Вибір уроку для оцінок тестів і завдань. Деталі: [CHANGELOG.md](CHANGELOG.md), [перевірки вибору уроку](GRADE_PLACEMENT_CHECKS.md).

Біля «📥 Оцінки» відкрийте **«Обрати урок»**. Укажіть період завершення робіт, натисніть «Показати роботи», а для потрібного тесту або завдання оберіть наявний урок за датою, номером і темою. Нові результати потраплять на цей урок, навіть якщо учні завершили роботу через тиждень. Журнал запам’ятовує вибір для наступних синхронізацій цієї роботи. Інші роботи та вже записані оцінки залишаються на своїх місцях; конфлікти потребують рішення вчителя. Повернути звичайну поведінку можна вибором «Автоматично за сесією та датою». Інструкція: **/help/#grade-lesson**.

У верхньому меню відкрийте **«API та обмін»**: підключення, списки учнів і поточні питання зібрані разом. **«Сповіщення»** показує причину та відкриває потрібне місце виправлення. Кнопка **«Резервна адреса»** додає іншу адресу того самого підтвердженого сайту; під час обміну журнал сам пробує доступні адреси, зокрема після відмови запиту API. Покрокова інструкція для користувача: **/help/#api-start**. Технічні параметри та історія доступні в «Додаткових налаштуваннях».

Передача списків використовує підтверджені ID учнів і зберігає псевдоніми для імпорту оцінок. Кнопка «📤 Учні» обробляє відповідь на поточній сторінці без помилки HTTP 405. У Центрі API → «Діагностика та помилки» можна завантажити знеособлений JSON-звіт; для адміністративного аудиту всіх класів доступна команда `python manage.py audit_integrations`. Завантаження звітів не запускає обмін даними й не змінює оцінки.

«Окремі учні» показує таблицю оцінок вибраного журналу, включно зі збереженою історією вимкнених підключень. Учні в рядках, уроки та роботи — у стовпцях. Пошук, джерело, семестр і місяць звужують перегляд. Клік оцінки відкриває роботи, а наявний окремий журнал доступний для редагування.

Онлайн-оновлення: [ONLINE_UPDATE_CHECKS.md](ONLINE_UPDATE_CHECKS.md). Сталі позакласні ID: [OUTSIDE_STUDENTS.md](OUTSIDE_STUDENTS.md).

У розділі «Оновлення системи» видно встановлену версію та її опис. «Перевірити наявність оновлень» отримує версію й зміни з GitHub; недоступність мережі показується помилкою. «⚡ Перезібрати поточну версію» збирає `HEAD` без завантаження іншої версії; checkout має відповідати встановленій версії та бути чистим.

Операція має п’ять етапів: код, збірка, перевірена копія, міграції/запуск, перевірка БД та образу. Термінал передає вивід команд під час виконання. 100% означає перевірений успіх. Під час збою після початку застосування оновлювач повертає образ, дані й ревізію коду; помилка відкату повідомляється окремо. Фінальний статус зберігається після перезавантаження сторінки; кнопка копіює діагностику. Відкат скасовує зміни даних після знімка, тому його слід запускати одразу після невдалого оновлення.

Для цієї можливості потрібен окремий контейнер `updater` із Docker socket і змонтованим checkout. Він працює лише у приватній мережі свого сайту. Повторні операції захищено спільним `.maintenance.lock`. Зібраний образ обирається у локальній `.env`; файли середовища й резервні копії не входять до Git. Якщо старий образ уже видалений, його код зберігається з чинного контейнера без томів і секретів середовища.


Локальний журнал для школи та особистих журналів учителів із nz.ua. Django, PostgreSQL 16, Gunicorn і Nginx; розгортання через Docker Compose. Інтерфейс українською.

## Можливості

- Створення першого суперадміністратора через браузер з одноразовим кодом початкового налаштування.
- Реєстрація школи з окремим адміністратором. Він керує лише своєю школою: учителями, роками, предметами, класами, призначеннями, учнями та аудитом. Технічний суперадміністратор — окрема роль.
- Вхід через nz.ua автоматично створює особистий профіль. Адміністрація не мусить заздалегідь створювати локальний обліковий запис учителя.
- Імпорт онлайн-журналів у локальну базу; уроки, оцінки й відвідування; попередній перегляд та підтвердження вивантаження в nz.ua.
- Додатковий локальний вхід, прив’язка журналу до локального профілю з підтвердженням його пароля та відв’язування зі збереженням записів за особистим профілем nz.ua.
- Тематичні, модульні, семестрові, річні оцінки та НУШ. Період починається після попередньої відповідної підсумкової оцінки, а за її відсутності — від початку семестру. Річний розрахунок охоплює навчальний рік. НУШ дає одну загальну оцінку з вибраних типів.
- Тижневий розклад учителя; спільний список часу уроків школи; час нового уроку вибирається зі списку.
- API списків учнів із дозволеними полями, ключами, строком дії, відкликанням і заміною ключів.
- Кілька зовнішніх API оцінок, налаштовувані поля JSON, зіставлення учнів і уроків за датою, захист від дублів і переписування ручних оцінок.
- Видиме джерело зовнішніх оцінок. Непогоджена ШІ-оцінка є попередньою: не входить до середнього, підсумкових оцінок, експорту чи вивантаження в nz.ua. Учитель погоджує або відхиляє її; заміну конфліктної оцінки підтверджує окремо.
- Імпорт учнів і тем без дублів уроків; експорт поточних уроків та календарного плану з ID, XLSX/PDF, історія змін.
- Повторне завантаження локального журналу з nz.ua та локальне видалення з підтвердженням; онлайн-журнал зберігається.
- Інструкція на /help/, версії та опис змін на /versions/, номер версії внизу кожної сторінки.

## Запуск на сервері

Потрібні Docker Engine, Docker Compose v2 з підтримкою --wait, Git, Bash, Python ≥ 3.12, util-linux (flock) і достатньо диска для образів та копій. Python для застосунку вже є в Docker; Python на сервері потрібний скриптам архівування.

Розгортання актуальної версії з гілки main:

~~~bash
git clone --branch main https://github.com/yrskrs/schooljournal.git
cd schooljournal
./setup.sh
# Відредагуйте .env під адресу сервера
docker compose config --quiet
docker compose up -d --build --wait --wait-timeout 180
~~~

Клонування публічного репозиторію через HTTPS не потребує SSH-ключа чи входу в GitHub.

setup.sh створює .env з випадковими SECRET_KEY, паролем PostgreSQL і INITIAL_SETUP_TOKEN, правами 0600 та без демонстраційних даних. У наявному .env додає відсутній або порожній INITIAL_SETUP_TOKEN, зберігаючи чинні секрети. Для LAN виконайте `./setup.sh --public-url http://192.168.1.13:8085` (підставте свою адресу): команда додає хост і CSRF origin без вилучення чинних адрес. Невідома адреса в ALLOWED_HOSTS спричиняє HTTP 400. Після зміни .env перестворіть web, щоб завантажити нове оточення. Вкажіть:

- ALLOWED_HOSTS: адреса або домен сервера, localhost,127.0.0.1 для перевірок контейнерів; без протоколу й порту.
- CSRF_TRUSTED_ORIGINS: повний URL із протоколом і портом, наприклад http://192.168.1.20:8085.
- WEB_PORT: порт сервісу, типово 8085; WEB_BIND: адреса прослуховування, типово 0.0.0.0.
- COMPOSE_PROJECT_NAME: стабільне ім’я розгортання, типово schooljournal. Не змінюйте для наявної бази: воно визначає імена Docker volumes.
- SCHOOL_REGISTRATION_ENABLED=True показує публічну реєстрацію; False вимикає кнопку й маршрут.
- Для HTTPS задайте довірений зовнішній проксі та SESSION_COOKIE_SECURE=True, CSRF_COOKIE_SECURE=True. Див. [DEPLOYMENT.md](DEPLOYMENT.md).

Відкрийте http://АДРЕСА:8085. На новому сервісі сторінка входу перенаправить до «Створити суперадміністратора». Введіть код INITIAL_SETUP_TOKEN із .env, логін, email і новий пароль двічі. Код нікому не передавайте: він дає право створити першого адміністратора. Створення користувача відбувається повністю у браузері; команда createsuperuser для першого запуску не потрібна.

Після збереження відкриється кабінет суперадміністратора. Форма початкового налаштування закривається назавжди для цієї бази, також після видалення цього користувача. Якщо суперадміністратор уже існує, сервіс одразу показує звичайний вхід. Наявного адміністратора та його пароль оновлення не змінює. INITIAL_SETUP_ENABLED=False явно вимикає браузерне початкове налаштування.

Далі зареєструйте школу або увійдіть через nz.ua. Публічна реєстрація школи дає права лише її адміністратора. Секрети й дані учнів не передаються у Git чи Docker image.

## Як працювати

### Адміністратор школи

1. Натисніть «Зареєструвати школу»; заповніть назву, дані адміністратора, логін і пароль. ЄДРПОУ необов’язковий; повторний код не приймається.
2. У «Навчальній структурі» додайте навчальний рік, предмети та класи. Перевірте автоматично створені семестри й уточніть їх за потреби через технічного адміністратора.
3. Зареєструйте вчителів і створіть їхні призначення на клас, предмет і рік.
4. Додайте учнів до класів. Переводьте їх спеціальною дією, щоб зберегти історію.
5. У «Час уроків» налаштуйте шкільний список дзвінків. Адміністратор може вибрати вчителя своєї школи в розкладі.

### Учитель: особистий профіль nz.ua

1. На сторінці входу натисніть «Увійти через портал nz.ua»; підтвердьте логін і пароль або чинний PHPSESSID. Пароль використовується для входу, але локально не зберігається.
2. Особистий профіль створиться автоматично. У «nz.ua» завантажте журнали та імпортуйте потрібний.
3. Вносьте уроки, теми, оцінки та відвідування в локальну копію.
4. За потреби прив’яжіть журнал до локального профілю, підтвердивши його логін і пароль. Відв’язування зберігає журнал і всі записи за особистим профілем nz.ua.
5. Для відправлення оцінок відкрийте синхронізацію, перегляньте зміни й конфлікти, підтвердьте відправлення та перевірте історію.

Нові локальні уроки не створюються автоматично в nz.ua; онлайн-вивантаження змін доступне для уроків із відповідною онлайн-прив’язкою.

Чинна онлайн-сесія та доступ до nz.ua потрібні для імпорту й синхронізації. Локальні записи зберігаються в PostgreSQL. За завершення сесії підтвердьте вхід повторно.

### Учитель: локальний профіль

Увійдіть за логіном, який створив адміністратор. Створіть журнал із доступного призначення. Час уроку вибирайте зі списку школи. У меню журналу виберіть підсумкову оцінку, перевірте дату, період і типи оцінок, перегляньте розрахунок та підтвердьте збереження.

«Розклад на тиждень» поєднує повторюваний розклад і вже створені уроки. Запис розкладу не створює оцінок автоматично. Зміна списку дзвінків не переписує час старих уроків.

### Копіювання календарних планів між класами

У розділі **«Копіювати теми з іншого класу»** додано автоматичну синхронізацію календарних планів за номерами уроків (№ 1, 2, 3...). Вчитель може обрати будь-який інший клас того самого предмета, перевірити відмінності, за потреби змінити напрямок синхронізації («⇄ Поміняти напрямок») та застосувати зміни. Якщо в одному класі є більше уроків (наприклад, 20 уроків проти 19 або менше), відсутні теми автоматично додаються до календарного плану цільового класу. Ручне копіювання за діапазоном збережено в окремій вкладці.

### Нумерація уроків для nz.ua та домашні завдання

Під час вивантаження тем уроків у nz.ua колонка «№ уроку» заповнюється порядковим номером уроку за календарним планом, а номер у щоденному розкладі зберігається у полі дзвінка. Дата виконання домашнього завдання за замовчуванням автоматично призначається на наступний урок.

### Імпорт тем і відновлення локального журналу

Для виправлення наявних тем відкрийте **«Імпорт тем» → «Поточні уроки та план XLSX»**, змініть теми, ДЗ або примітки й імпортуйте файл. Залишайте ID і дати без змін. Попередній перегляд показує конкретний урок або нову тему для кожного рядка. **«Лише оновити наявні»** не створює нових записів. Повторний імпорт оновлює той самий урок та зберігає його оцінки, відвідування, час і прив’язку nz.ua. Порожні ДЗ та примітки очищають поля.

Старі XLSX/CSV без ID підтримуються: один урок на дату зіставляється незалежно від номера; для кількох уроків потрібна колонка «Номер уроку на дату» або поточний експорт із ID. «№ уроку» означає номер теми плану, а не номер уроку на дату. Неоднозначні та повторні рядки показуються як помилки й пропускаються; дати поза навчальним роком не імпортуються. Порожній шаблон не містить прикладів із застарілими датами.

**«Лише календарний план»** зберігає дати як заплановані та не створює уроків. Експорт містить і проведені уроки, і майбутні теми; вид запису PLAN зберігає лише тему плану навіть із датою.

**«Оновити з nz.ua»** доповнює локальні дані зі збереженням локальних змін. **«Завантажити заново з nz.ua»** після підтвердження замінює всі локальні уроки, план, оцінки, відвідування, підсумки та розклад цього журналу онлайн-даними. Посилання журналу й підключення тестів/завдань залишаються; оцінки з робіт отримуйте окремими кнопками. Дані спочатку завантажуються, потім записуються однією транзакцією: помилка зберігає попередній стан. Порожній нерозпізнаний онлайн-журнал не очищає локальні записи.

У **«Дії журналу» → «Видалити локальний журнал»** можна видалити саме локальну копію та її підключення, а потім знову імпортувати її з розділу **«nz.ua»**. На сторінці підтвердження є кількість записів і посилання експорту. Журнал у nz.ua, спільний клас та учні залишаються. Видалення і заміна доступні власнику або адміністратору та записуються в аудит; зв’язки окремого позакласного журналу потрібно спочатку розв’язати на сторінці результатів.

Онлайн-завантаження охоплює всі сторінки журналу nz.ua. Якщо будь-яка сторінка недоступна, сесія завершилася або структура не розпізнана, імпорт переривається до зміни локальних даних. Це стосується також «Завантажити заново з nz.ua».

### API та роботи учнів

У **«Списки та синхронізація»** виберіть **«Ваш клас» → «Показати журнали»**. Список містить класи з ваших доступних неархівних журналів, зокрема особистих nz.ua, і працює без серверних налаштувань фонового обміну. Для потрібного предмета відкрийте **«Підключити тести / завдання»** або скористайтеся **«Передати список»** біля вже підключеного джерела. Показано час останньої передачі та кількість ігнорованих учнів. Оцінки отримуються окремими кнопками в журналі.

Якщо журналів ще немає, сторінка пропонує створити локальний журнал або завантажити його з nz.ua. Додатковий фоновий обмін спільними класами й конфлікти доступні в окремому згорнутому блоці. Його неналаштований стан не заважає звичайній передачі учнів із журналу.

На сайті тестів або завдань створіть ключ API й скопіюйте адресу сайту та ключ окремо. У потрібному журналі відкрийте «Підключити тести / завдання», вставте адресу джерела з IP і портом та окремо ключ, виберіть клас і предмет за назвами й підтвердьте учнів. Журнал передає копію класу та учнів у незалежну місцеву базу джерела. Підключення необов’язкове; кожен сайт працює самостійно.

Оцінки отримуйте кнопками «Синхронізувати з тестами» та «Синхронізувати із завданнями». Повторне отримання не створює дублів. Учитель бачить джерело й статус, погоджує ШІ-оцінки та окремо підтверджує заміну ручної оцінки. Непогоджені оцінки сервер блокує для nz.ua. Діти без відповідності та результати з помилками зберігаються в «Позакласних учнях та результатах».

Після зміни IP відредагуйте адресу того самого підключення: прив’язки учнів і вже імпортованих оцінок збережуться. Джерело має бути доступне серверу журналу; різні LAN потребують маршруту або приватного VPN. Без зв’язку локальна робота залишається доступною.

Журнал і завдання використовують окремі cookies сесії та CSRF. Чинна власна стара сесія переноситься автоматично. Якщо її вже перезаписав інший сайт або сайт відкрито за іншою IP-адресою, увійдіть один раз. Після оновлення перезавантажте вкладки для отримання нового JavaScript.

Для інших серверів доступне розширене налаштування в «Профілі та API»: видача учнів за ключем, повний URL зовнішнього API та явне зіставлення полів і записів. [Інструкція й контракт API v2](INTEGRATION.md), [загальний API v1](EXTERNAL_API.md), [результати перевірок інтеграції](INTEGRATION_CHECKS.md). Інструкція користувача доступна без входу на /help/.

### Ігнорування учнів і результатів

«Ігнорувати за дату» переносить результат до ігнорованих. Якщо в учня немає інших активних результатів, його картка «Підтвердити відповідність» зникає. Інші дати залишаються доступними. «Відновити» повертає запис у чергу, оцінку потрібно імпортувати окремою дією. Повторний імпорт і виправлення у джерелі не скасовують ігнорування. Наявні оцінки не видаляються.

Натисніть номер учня в таблиці та позначте «Ігноровано (сімейна форма)». Меню відкривається поверх таблиці; повторне натискання позначки відновлює синхронізацію й оцінювання. Статус стосується лише цього журналу. Оцінки та сам учень збережені.

### Відповідності та позакласні записи

На сторінці «Позакласні учні та результати» оберіть справжнього учня й підтвердьте відповідність або натисніть окрему кнопку «Залишити позакласним». На сторінці «Окремі учні» збережені результати показані таблицею за датами й темами уроків. Перегляд не створює класу або уроків; «Залишити позакласним» може створити окремий локальний журнал для редагування, як у попередніх випусках. Для підтвердженої відповідності учню основного класу оцінки додаються наступною синхронізацією або кнопкою збереженого результату.

Для вигаданого запису відкрийте «Видалити позакласний запис», підтвердьте й натисніть «Видалити назавжди». Очищаються його збережені результати, а для нового окремого профілю — також його локальні записи. Основні учні й їхні вже імпортовані оцінки зберігаються. Повторний обмін не повертає видалену ідентичність. Роботи на джерелі видаляйте окремо; сайти незалежні. Автор і час дії доступні в «Історії відповідностей та видалень».

У вже створеному окремому журналі позакласних учнів натисніть номер учня та «Видалити позакласного учня та оцінки». Це підтримує також таблиці попередніх випусків без автоматичного зіставлення імен. Для старого профілю видаліть також його запис джерела на сторінці результатів; для нового стабільно пов’язаного профілю обидва записи видаляються разом. Учні з іншими прив’язками захищені.

## Оновлення інтерфейсу та ігнорування учнів

У журналі кнопка **«Оновити дані»** отримує актуальний стан без повного перезавантаження. Збереження уроків, видалення, завантаження з nz.ua та вивантаження змін автоматично оновлюють таблицю й позначки. Прокрутка сторінки й таблиць, пошук і фільтри зберігаються. Після звичайного переходу або перезавантаження позиція відновлюється в межах тієї самої вкладки протягом 30 хвилин; у браузері зберігаються лише координати й ідентифікатор рядка.

Індикатор унизу показує активні запити. Помилка, скасування або завершення прибирають його. Через 120 секунд очікування припиняється; перед повторною дією натисніть «Оновити дані», оскільки сервер міг уже зберегти частину змін. Вивантаження nz.ua показує справжню причину відмови; сам HTTP 200 не є помилкою. Неоднозначне підтвердження перевіряється за фактичним значенням клітинки.

**«Підключення та імпорт»** містить налаштування джерел, отримання оцінок з робіт та імпорти. Підменю підлаштовується до меж екрана; якщо висоти замало, прокрутіть його до потрібного пункту. Закрити підменю можна повторним натисканням заголовка, клавішею Escape або натисканням поза ним. На малих екранах загальну навігацію відкриває **«Меню»**.

Ігнорування учня через меню його номера не передає новий профіль у джерела. Для раніше зіставленої копії журнал передає неактивний статус: учень зникає з доступних списків тестів і завдань, а його ID та історія робіт залишаються. Повторне натискання відновлює активність. Підключені сучасні джерела оновлюються одразу. Якщо джерело недоступне, повторіть **«Передати список»** на сторінці підключення після відновлення зв’язку; якщо джерело повернуло конфлікт ПІБ, підтвердьте рішення там. Локальне ігнорування діє незалежно від доступності джерела.

## Оновлення та резервні копії

~~~bash
./backup.sh
./update.sh origin/main
./restore.sh --check backups/НАЗВА.tar.gz
./restore.sh backups/НАЗВА.tar.gz --yes
~~~

Скрипти працюють із кореня репозиторію незалежно від поточної папки. .env читає Docker Compose; його вміст не виконується як shell-код. Паралельні операції обмежені flock.

- backup.sh зупиняє web/nginx для узгодженого знімка, копіює PostgreSQL, media, код та поточний image, додає SHA-256 і метадані, перевіряє архів і запускає сервіс. Архіви в backups/ мають права 0600.
- update.sh вимагає чистий Git checkout. Отримує ревізію, допускає лише рух уперед, збирає image у відокремленому worktree, перевіряє Django, зупиняє запис, робить копію та застосовує міграції. Перевіряє Django, PostgreSQL і Nginx. За помилки після копії автоматично відновлює знімок і повертає ненульовий код.
- restore.sh --check перевіряє архів без зміни даних. restore.sh ARCHIVE --yes замінює базу, media та код, завантажує збережений image і перевіряє сервіс. Перед цим робить safety backup. За невдалого відновлення даних сервіс лишається зупиненим; помилка не приховується.
- .release-image.yaml зберігає активний image після оновлення чи відновлення. Скрипти додають його автоматично. Для ручних Compose-команд використовуйте ./service.sh, наприклад ./service.sh ps.

Копії від 1.3.12 включають пакет обміну school_sync. Для старих архівів відновлювач зберігає наявний пакет; Git checkout потрібної ревізії повертає відповідний код.

Архіви містять персональні дані та онлайн-сесії: зберігайте приватно, копіюйте на інший носій. .env до архіву не входить; збережіть його окремо у захищеному сховищі. Відновлюйте лише власні довірені архіви. Старі копії без контрольних сум новим restore.sh не підтримуються.

Перед відкатом зробіть свіжу копію поточних даних; стару БД поверх нових оцінок не відновлюйте. Зберігайте адитивні міграції. Версії до 1.3.3 не враховують позначки видалення: до повернення актуального образу не отримуйте оцінки чи списки для очищених записів.

Деталі перенесення, HTTPS і відновлення: [DEPLOYMENT.md](DEPLOYMENT.md).

## Розробка й перевірки

~~~bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py check --settings=config.test_settings
.venv/bin/python manage.py makemigrations --check --dry-run --settings=config.test_settings
.venv/bin/python manage.py test --settings=config.test_settings --noinput
node tests/journal_scheduling_check.js
node tests/student_menu_check.js
.venv/bin/python -m unittest scripts.test_update_helpers
for script in *.sh scripts/*.sh; do bash -n "$script"; done
~~~

Тести використовують вигадані дані, SQLite в пам’яті й не читають робочий .env. Виклики nz.ua підмінено; фактичну онлайн-синхронізацію перевіряйте окремо на дозволеному тестовому журналі.

Для локальної розробки: docker compose -f compose.yaml -f compose.dev.yaml up -d --build. Production Compose не монтує вихідний код чи приватні папки в контейнер.

У режимі `compose.dev.yaml` Python-процес автоматично перезавантажується після змін коду та метаданих версії. Якщо код змонтовано в контейнер вручну без цього режиму, після змін виконайте `./service.sh restart web`: нові шаблони зі старими маршрутами можуть спричинити HTTP 500 після входу. Звичайне оновлення вкладки цього не виправляє. Після змін CSS/JavaScript також перезапустіть `web`, щоб оновити зібрані статичні файли.

GitHub Actions перевіряє Django, міграції, тести, JavaScript, Bash і збірку Docker. Порядок релізу: [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md). Джерела версії — VERSION і RELEASES.json; історія — [CHANGELOG.md](CHANGELOG.md).

## Відновлення адміністратора старого демонстраційного запуску

Демонстраційне наповнення більше не створює суперадміністратора. Наявні облікові записи залишаються. Власник сервера може явно дозволити одноразове відновлення через браузер зі збереженням ID користувача, шкіл, журналів і оцінок:

1. Зробіть резервну копію (`./backup.sh`). Знайдіть потрібного суперадміністратора в базі через приватну консоль сервера.
2. У .env задайте `INITIAL_SETUP_RECOVERY_USER_ID` відповідно до його PK та новий випадковий `INITIAL_SETUP_TOKEN` довжиною щонайменше 32 символи. Залиште `INITIAL_SETUP_ENABLED=True`; код не публікуйте.
3. Виконайте `./service.sh up -d --force-recreate web`, потім `./service.sh exec -T web python manage.py prepare_admin_recovery --username ПОТОЧНИЙ_ЛОГІН`.
4. Перезапустіть nginx (`./service.sh restart nginx`), якщо після перестворення web він ще використовує стару адресу контейнера. Відкрийте сторінку входу, введіть серверний код та задайте власний логін і пароль.
5. Після успішного збереження форма закриється. Поверніть `INITIAL_SETUP_RECOVERY_USER_ID=0` та перестворіть web. Команда тимчасово вимикає старий вхід цього адміністратора; після правильного коду й нового пароля обліковий запис активується. Саме налаштування ID не відкриває завершений перший запуск; команда доступна лише на сервері.

Без явної команди на сервері та правильного коду змінити наявного адміністратора неможливо. Зміни схеми БД у цьому випуску відсутні. Для відкату поверніть попередній образ/код за загальною інструкцією відкату, зберігши актуальні ALLOWED_HOSTS і CSRF_TRUSTED_ORIGINS; введені користувачем облікові дані сумісні з 1.1.0.
