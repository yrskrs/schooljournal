# Електронний шкільний журнал — 1.0.0

Локальний журнал для школи та особистих журналів учителів із nz.ua. Django, PostgreSQL 16, Gunicorn і Nginx; розгортання через Docker Compose. Інтерфейс українською.

## Можливості

- Реєстрація школи з окремим адміністратором. Він керує лише своєю школою: учителями, роками, предметами, класами, призначеннями, учнями та аудитом. Технічний суперадміністратор — окрема роль.
- Вхід через nz.ua автоматично створює особистий профіль. Адміністрація не мусить заздалегідь створювати локальний обліковий запис учителя.
- Імпорт онлайн-журналів у локальну базу; уроки, оцінки й відвідування; попередній перегляд та підтвердження вивантаження в nz.ua.
- Додатковий локальний вхід, прив’язка журналу до локального профілю з підтвердженням його пароля та відв’язування зі збереженням записів за особистим профілем nz.ua.
- Тематичні, модульні, семестрові, річні оцінки та НУШ. Період починається після попередньої відповідної підсумкової оцінки, а за її відсутності — від початку семестру. Річний розрахунок охоплює навчальний рік. НУШ дає одну загальну оцінку з вибраних типів.
- Тижневий розклад учителя; спільний список часу уроків школи; час нового уроку вибирається зі списку.
- API списків учнів із дозволеними полями, ключами, строком дії, відкликанням і заміною ключів.
- Кілька зовнішніх API оцінок, налаштовувані поля JSON, зіставлення учнів і уроків за датою, захист від дублів і переписування ручних оцінок.
- Видиме джерело зовнішніх оцінок. Непогоджена ШІ-оцінка є попередньою: не входить до середнього, підсумкових оцінок, експорту чи вивантаження в nz.ua. Учитель погоджує або відхиляє її; заміну конфліктної оцінки підтверджує окремо.
- Імпорт учнів і тем, експорт XLSX/PDF, історія змін, показ учнів, які вибули.
- Інструкція на /help/, версії та опис змін на /versions/, номер версії внизу кожної сторінки.

## Запуск на сервері

Потрібні Docker Engine, Docker Compose v2 з підтримкою --wait, Git, Bash, Python ≥ 3.12, util-linux (flock) і достатньо диска для образів та копій. Python для застосунку вже є в Docker; Python на сервері потрібний скриптам архівування.

Після публікації гілки release/v1.0.0:

~~~bash
git clone --branch release/v1.0.0 git@github.com:yrskrs/schooljournal.git
cd schooljournal
./setup.sh
# Відредагуйте .env під адресу сервера
docker compose config --quiet
docker compose up -d --build --wait --wait-timeout 180
docker compose exec web python manage.py createsuperuser
~~~

Для читання публічного репозиторію можна використати HTTPS замість SSH. Після злиття релізу в main розгортайте main. Гілку та ключ SSH налаштуйте до виконання команд.

setup.sh створює .env з випадковими SECRET_KEY і паролем PostgreSQL, правами 0600 та без демонстраційних даних. Наявний .env не переписує. Вкажіть:

- ALLOWED_HOSTS: адреса або домен сервера, localhost,127.0.0.1 для перевірок контейнерів; без протоколу й порту.
- CSRF_TRUSTED_ORIGINS: повний URL із протоколом і портом, наприклад http://192.168.1.20:8080.
- WEB_PORT: порт сервісу, типово 8080; WEB_BIND: адреса прослуховування, типово 0.0.0.0.
- COMPOSE_PROJECT_NAME: стабільне ім’я розгортання, типово schooljournal. Не змінюйте для наявної бази: воно визначає імена Docker volumes.
- SCHOOL_REGISTRATION_ENABLED=True показує публічну реєстрацію; False вимикає кнопку й маршрут.
- Для HTTPS задайте довірений зовнішній проксі та SESSION_COOKIE_SECURE=True, CSRF_COOKIE_SECURE=True. Див. [DEPLOYMENT.md](DEPLOYMENT.md).

Відкрийте http://АДРЕСА:8080. Зареєструйте школу або увійдіть через nz.ua. createsuperuser створює технічного суперадміністратора; публічна реєстрація таких прав не дає. Секрети й дані учнів не передаються у Git чи Docker image.

## Як працювати

### Адміністратор школи

1. Натисніть «Зареєструвати школу»; заповніть назву, дані адміністратора, логін і пароль. ЄДРПОУ необов’язковий; повторний код не приймається.
2. У «Навчальній структурі» додайте навчальний рік, предмети та класи. Перевірте автоматично створені семестри й уточніть їх за потреби через технічного адміністратора.
3. Зареєструйте вчителів і створіть їхні призначення на клас, предмет і рік.
4. Додайте учнів до класів. Переводьте їх спеціальною дією, щоб зберегти історію.
5. У «Час уроків» налаштуйте шкільний список дзвінків. Адміністратор може вибрати вчителя своєї школи в розкладі.

### Учитель: особистий профіль nz.ua

1. На сторінці входу натисніть «Увійти через портал nz.ua»; підтвердьте логін і пароль або чинний PHPSESSID. Пароль використовується для входу, але локально не зберігається.
2. Особистий профіль створиться автоматично. У «nz.ua» завантажте журнали та імпортуйте потрібний.
3. Вносьте уроки, теми, оцінки та відвідування в локальну копію.
4. За потреби прив’яжіть журнал до локального профілю, підтвердивши його логін і пароль. Відв’язування зберігає журнал і всі записи за особистим профілем nz.ua.
5. Для відправлення оцінок відкрийте синхронізацію, перегляньте зміни й конфлікти, підтвердьте відправлення та перевірте історію.

Нові локальні уроки не створюються автоматично в nz.ua; онлайн-вивантаження змін доступне для уроків із відповідною онлайн-прив’язкою.

Чинна онлайн-сесія та доступ до nz.ua потрібні для імпорту й синхронізації. Локальні записи зберігаються в PostgreSQL. За завершення сесії підтвердьте вхід повторно.

### Учитель: локальний профіль

Увійдіть за логіном, який створив адміністратор. Створіть журнал із доступного призначення. Час уроку вибирайте зі списку школи. У меню журналу виберіть підсумкову оцінку, перевірте дату, період і типи оцінок, перегляньте розрахунок та підтвердьте збереження.

«Розклад на тиждень» поєднує повторюваний розклад і вже створені уроки. Запис розкладу не створює оцінок автоматично. Зміна списку дзвінків не переписує час старих уроків.

### API та роботи учнів

У журналі відкрийте «Інтеграції / API». Для видачі учнів оберіть поля й створіть ключ; збережіть його одразу. Для отримання оцінок додайте повний URL API сервера робіт, ключ і зіставлення полів та учнів.

Сайт робіт http://192.168.1.13:8080/ відомий, але маршрут його API ще розробляється. Заповнюйте URL після готовності маршруту. Контракт і приклади запитів: [EXTERNAL_API.md](EXTERNAL_API.md).

Оцінки надходять за явним запитом журналу. Повторне отримання не створює дублів. Учитель бачить джерело й статус, погоджує ШІ-оцінки та окремо підтверджує заміну ручної оцінки. Непогоджені оцінки сервер блокує для nz.ua. Повна інструкція доступна без входу на /help/.

## Оновлення та резервні копії

~~~bash
./backup.sh
./update.sh origin/release/v1.0.0
# Після переходу на main:
./update.sh origin/main
./restore.sh --check backups/НАЗВА.tar.gz
./restore.sh backups/НАЗВА.tar.gz --yes
~~~

Скрипти працюють із кореня репозиторію незалежно від поточної папки. .env читає Docker Compose; його вміст не виконується як shell-код. Паралельні операції обмежені flock.

- backup.sh зупиняє web/nginx для узгодженого знімка, копіює PostgreSQL, media, код та поточний image, додає SHA-256 і метадані, перевіряє архів і запускає сервіс. Архіви в backups/ мають права 0600.
- update.sh вимагає чистий Git checkout. Отримує ревізію, допускає лише рух уперед, збирає image у відокремленому worktree, перевіряє Django, зупиняє запис, робить копію та застосовує міграції. Перевіряє Django, PostgreSQL і Nginx. За помилки після копії автоматично відновлює знімок і повертає ненульовий код.
- restore.sh --check перевіряє архів без зміни даних. restore.sh ARCHIVE --yes замінює базу, media та код, завантажує збережений image і перевіряє сервіс. Перед цим робить safety backup. За невдалого відновлення даних сервіс лишається зупиненим; помилка не приховується.
- .release-image.yaml зберігає активний image після оновлення чи відновлення. Скрипти додають його автоматично. Для ручних Compose-команд використовуйте ./service.sh, наприклад ./service.sh ps.

Архіви містять персональні дані та онлайн-сесії: зберігайте приватно, копіюйте на інший носій. .env до архіву не входить; збережіть його окремо у захищеному сховищі. Відновлюйте лише власні довірені архіви. Старі копії без контрольних сум новим restore.sh не підтримуються.

Деталі перенесення, HTTPS і відновлення: [DEPLOYMENT.md](DEPLOYMENT.md).

## Розробка й перевірки

~~~bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py check --settings=config.test_settings
.venv/bin/python manage.py makemigrations --check --dry-run --settings=config.test_settings
.venv/bin/python manage.py test --settings=config.test_settings --noinput
node tests/journal_scheduling_check.js
for script in *.sh scripts/*.sh; do bash -n "$script"; done
~~~

Тести використовують вигадані дані, SQLite в пам’яті й не читають робочий .env. Виклики nz.ua підмінено; фактичну онлайн-синхронізацію перевіряйте окремо на дозволеному тестовому журналі.

Для локальної розробки: docker compose -f compose.yaml -f compose.dev.yaml up -d --build. Production Compose не монтує вихідний код чи приватні папки в контейнер.

GitHub Actions перевіряє Django, міграції, тести, JavaScript, Bash і збірку Docker. Порядок релізу: [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md). Джерела версії — VERSION і RELEASES.json; історія — [CHANGELOG.md](CHANGELOG.md).
