# Перевірки інтеграції — 2026-10-10

## Обсяг і версії

Реалізовано та розгорнуто API v2 для трьох незалежних проєктів. Списки зберігаються локально, учасники рівноправні, зіставлення наявних учнів явне за ID, суперечності вирішуються вручну. Фоновий обмін передає лише списки. Остаточні оцінки журнал отримує двома окремими POST-кнопками вчителя; автоматично приймаються лише цілі 1–12 зі шкали 12. Ручні оцінки захищені.

| Проєкт | Версія / образ | Ревізія коду в образі | Браузерний порт |
|---|---|---|---|
| schooltest5 | 1.3.0 / `schooltest5-app:1.3.0` | `5efc8fe` | 8080 |
| schoolwork2 | 4.2.0 / `schoolwork2-app:4.2.0` | `9cf2cae` | 8000 |
| schooljournal | 1.1.0 / `schooljournal-web:1.1.0` | `b63a2ef` | 8085 |

Образи перевірено окремо: OCI version/revision/source, імпорт застосунку, власні джерела версій, описи актуального випуску, відсутність робочих `.env`, Git, баз та завантажень. Версії реально запущених сайтів звірено через HTTP. Наступні коміти документації не змінюють код цих образів. Випуск журналу 1.0.1 і його початкове налаштування збережено.

## Початкові перевірки

Прочитано моделі, права, призначення класам, API, наявне підтягування імен, правила повторних спроб, Docker/Compose, конфігурацію, документацію й тести. Початкові робочі дерева джерел не містили сторонніх змін. Базові ревізії тестів/завдань: `5daf8f7` / `b5ec0f5`; журнал інтегровано поверх незалежного випуску `7661f57`.

schooltest5: початкові 16 перевірок основних сценаріїв пройшли. Журнал: початкові 268 тестів пройшли. schoolwork2: із 580 тестів два мали застарілі очікування (строгий режим аналізу неповної ШІ-відповіді та кількість наявних вкладок налаштувань); очікування виправлено, захист ШІ-аналізу не послаблено. Два тести блокувань не виконувалися на SQLite; остаточно виконані на PostgreSQL.

## Наскрізний сценарій у Docker

Виконано `tests/integration/run.py` репозиторію schooljournal на остаточних образах. Окремий Compose-проєкт `school-api-checks`: три PostgreSQL у tmpfs, вигадані дані, без робочих `.env`, баз чи томів. Порти 19080/19000/19085 слухали лише 127.0.0.1. Перевірено реальні HTTP-форми та серверні кнопки:

- Явне зіставлення класу й учня через форми вчителя; три локальні списки узгоджені без пошуку тотожності за ПІБ.
- Фоновий обмін не створює оцінок; Bearer, POST, учительська сесія, CSRF та права перевіряються сервером.
- Дві кнопки окремо імпортують тести й завдання. Повторний запуск не дублює записи; виправлення оновлюються лише після натискання.
- Ручна оцінка залишається після виправлення джерела; дробові, рівневі, нульові та позашкальні значення потребують ручного рішення.
- Недоступність тестів не блокує завдання або журнал. Новий учень надходить після відновлення зв’язку.
- Одночасні місцеві зміни створюють видимий конфлікт; рішення вчителя через потрібну форму поширюється на всі сайти.
- Кожен сайт окремо, при зупинених інших двох, зберігає свою основну операцію: роботу учня, завершену спробу тесту або ручну оцінку.
- Накопичена перездача отримана після недоступності журналу зі стабільним ID результату.
- Restart зберігає оцінки, місцеві ID та metadata списків.
- 501 додаткове вигадане завдання отримано через дві реальні сторінки API; зайняті клітинки залишаються конфліктами.

Після появи додаткової форми редагування сценарій уточнено, щоб він обирав саме `action=resolve`; весь сценарій повторно пройшов на свіжих базах.

## Робоче розгортання

Усі три образи перезібрано й контейнери оновлено. Сайт завдань та його AI worker використовують один образ 4.2.0. Усі 8 робочих контейнерів (веб, worker, nginx, БД) здорові. Адитивні міграції застосовано. Помилок запуску інтеграції не виявлено.

Спільна мережа `school-integration` має лише вебсервіси й чинний worker, з унікальними aliases `schooltest-api`, `schoolwork-api`, `schooljournal-api`, `schoolwork-worker`. БД лишилися у приватних мережах. Загальний автоматичний alias `app` прибрано зі спільної мережі утилітою `scripts/configure_integration_network.py`. Перевірено всі шість напрямків API за адресами серверної конфігурації, успішні фонові обміни та 401 без ключа. CORS для цього server-to-server обміну не потрібен; браузерні форми працюють зі своїм сайтом.

Браузерні адреси збережено: `http://HOST:8080`, `http://HOST:8000`, `http://HOST:8085`. Публікація БД збережена: 5432 / 5433; журнал свою БД не публікує. Конфліктів портів, імен Compose, контейнерів або aliases немає. Чинний nginx журналу перевірено через 8085; нових зовнішніх маршрутів не відкрито.

До міграцій зроблено узгоджені резервні копії зі зупиненими записами, перевірено `pg_restore --list` та SHA256. Збережено попередні образи. Старий немонтований файл із `/app/app/static/uploads` тестів перенесено в постійний том до перестворення контейнера. Хеші **всіх старих полів усіх рядків** контрольних таблиць і всіх завантажень збіглися після міграцій та повторно після restart:

| Дані | До / після / після restart |
|---|---|
| Тести: учителі / тести / сесії / спроби / файли | 1 / 1 / 1 / 1 / 3 |
| Завдання: класи / учні / завдання / здані роботи / файли | 16 / 26 / 34 / 47 / 2982 |
| Журнал: учні / класи / зарахування / журнали / уроки / оцінки | 79 / 5 / 79 / 4 / 33 / 98 |

**Робочі списки не об’єднувалися за іменами, робочі оцінки не імпортувалися тестами.** Учитель має спочатку приєднати реальні класи та явно зіставити наявні ID у «Списки та синхронізація», а тоді створити власні ключі оцінок і підключення v2 у журналі. Успішна порожня відповідь peers до такого приєднання не очищає місцеві записи. Область журналу налаштовано на місцеву школу 1 та поточний навчальний рік 2. Детальні дії: [INTEGRATION.md](INTEGRATION.md).

## Відкат і публікація

Приватна копія в кожному проєкті: `backups/before-api-v2-20261010-155329/`. Вона містить PostgreSQL dump, архіви файлів, попередню `.env`, baseline Compose, SHA256, `ROLLBACK.txt` та перевірений `rollback-image.yaml`. Збережені образи: `schooltest5-rollback:before-api-v2`, `schoolwork2-rollback:before-api-v2`, `schooljournal-rollback:before-api-v2`. Конфігурації відкату перевірено через Compose; сам відкат робочого середовища не виконувався.

Перед відкатом зупиніть запис, зробіть **нову** копію та додайте відповідний `rollback-image.yaml` останнім override до чинних Compose-файлів. Це вимикає peers, повертає попередній образ і зберігає томи, включно з новим томом загальних завантажень тестів. Повне відновлення старої БД потребує окремого рішення щодо накопичених даних. Не видаляйте томи й не застосовуйте зворотні міграції integration metadata. Обмеження попереднього коду щодо однакових ПІБ описано в INTEGRATION.md.

Перевірено diff та шляхи публікації, відсутність фактичних ключів із серверних конфігурацій у доданих рядках. Секрети, робочі `.env`, override, бази, резервні копії й завантаження у Git не включені. Гілка кожного репозиторію: `feature/service-api-integration`; main не зливається, force push не використовується.

## Межі перевірки

Обов’язкові сценарії інтеграції перевірені на вигаданих даних у реальних контейнерах; робоче середовище перевірене на запуск, адреси, авторизацію, фоновий обмін і збереження наявних даних. Реальні учні потребують ручного початкового зіставлення вчителем; це не замінюється автоматичним пошуком за ПІБ.

Графічний браузер у доступному середовищі відсутній: візуальна перевірка не виконувалася, форми та кнопки перевірено через HTTP, JavaScript — окремими сценаріями. Інші Docker-хости, зовнішні домени/HTTPS/firewall та сторонні reverse proxy не були частиною цього розгортання і не перевірялися. Відкриття локального журналу назовні не виконувалося.
